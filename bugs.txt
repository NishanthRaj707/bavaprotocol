--------------------------------------------------------------------------------
PART 2: DISCOVERED HIDDEN BUGS (STATIC ANALYSIS)
--------------------------------------------------------------------------------

[BUG-H05] - [MEDIUM] - Unconditional Byte Reversal Corrupting Big-Endian MCUs and Byte Arrays
Status: TACKLED
Root Cause in Code:
In `include/bava.h`, `bava_htons()` and `bava_htonl()` performed unconditional byte swapping regardless of MCU architecture. In `src/bava_tx.c` and `src/bava_dict.c`, automatic byte swapping for lengths 2 and 4 corrupted raw byte arrays (`uint8_t[2]`, `uint8_t[4]`, floats).
Resolution:
1. `bava_htons()` and `bava_htonl()` now conditionally evaluate target endianness (`__BYTE_ORDER__ == __ORDER_BIG_ENDIAN__`). On big-endian MCUs, they are zero-cost no-ops.
2. Added explicit type metadata flags (`BAVA_TYPE_RAW`, `BAVA_TYPE_U16`, `BAVA_TYPE_U32`).
3. Payload bytes default to raw byte sequences (`BAVA_TYPE_RAW`), guaranteeing zero array or struct corruption. Byte swapping is strictly restricted to variables explicitly tagged with `BAVA_TYPE_U16` / `BAVA_TYPE_U32`.

[BUG-H06] - [MEDIUM] - Remote Read Request for Unregistered ID Causes Silent Remote Hang
Status: TACKLED
Root Cause in Code:
In `src/bava_tx.c` (`bava_cmd_read_request()`), if a requested variable ID was not registered in the dictionary, the function returned silently without transmitting a response, causing the remote requester to hang until timeout.
Resolution:
`bava_cmd_read_request()` and `bava_bus_cmd_read_request()` now immediately reply with a fast error response (`BAVA_READ_RESP` with length 0). In `src/bava_state.c`, receiving a zero-length read response immediately clears `is_waiting_ack = false` and invokes `error_callback(id, BAVA_STATUS_ERR_NOT_FOUND)`, failing fast in O(1).

[BUG-H07] - [MEDIUM] - Desynchronization in `bava_send_raw_write` When Payload Pointer is NULL
Status: TACKLED
Root Cause in Code:
In `src/bava_tx.c` (`bava_internal_send_packet()`), if `payload == NULL` while `len > 0`, `payload_size` was written as `len` in the header, while skipping payload bytes and computing CRC with length 0. The receiver read CRC bytes as payload.
Resolution:
`payload_size` is now defensively guarded: `uint8_t payload_size = (payload == NULL) ? 0U : ((len > BAVA_MAX_PAYLOAD) ? BAVA_MAX_PAYLOAD : len);`. If `payload == NULL`, `payload_size` is strictly forced to 0U, ensuring frame and CRC consistency.

[BUG-H09] - [LOW] - COBS Buffer Overflow Risk When `BAVA_MAX_PAYLOAD` >= 248
Status: TACKLED
Root Cause in Code:
In `include/bava.h`, `BAVA_COBS_FRAME_MAX_SIZE` was defined as `BAVA_RAW_FRAME_MAX_SIZE + 2U`. For raw frames exceeding 254 bytes, COBS overhead requires 2 code bytes plus trailing delimiter (total +3 bytes), causing a 1-byte out-of-bounds write.
Resolution:
Defined `BAVA_COBS_FRAME_MAX_SIZE` as `(BAVA_RAW_FRAME_MAX_SIZE + (BAVA_RAW_FRAME_MAX_SIZE / 254U) + 2U)`. Mathematically accommodates worst-case COBS expansion for any payload size.

[BUG-H10] - [LOW] - MISRA-C Rule 10.1 & 10.4 Integer Promotion Violations in Bitwise Operations
Status: TACKLED
Root Cause in Code:
In `src/bava_crc.c` and `include/bava.h`, bitwise shift operations on `uint16_t` promoted operands to signed `int`. On 16-bit architectures, shifting bit 15 invoked signed overflow undefined behavior. Integer constants lacked unsigned `U` suffixes.
Resolution:
All CRC bitwise shifts, masks, and constants in `src/bava_crc.c`, `src/bava_state.c`, and `include/bava.h` now feature explicit casts and unsigned suffixes (`U`), eliminating signed promotions and ensuring full MISRA-C:2012 Rules 10.1, 10.3, and 10.4 compliance.
